## Core Concepts

- **POS architecture**: Odoo 19 POS uses OWL components and a dedicated JavaScript environment. Models loaded into client-side cache at session start.
- **POS components**: Action popup (user operations), screen UI (order/product display), receipt (print/customer copy), payment (terminal integration).

## Techniques

- **Add custom JS/SCSS**: Extend POS models via `pos.js`. Add files to `'point_of_sale.assets'` bundle.
- **Custom action button**: `pos.config` → `use_action_popup`. Extend `ChromeWidget` to add buttons to the Actions popup.
- **RPC from POS**: `this.env.services.rpc({model: 'hostel.room', method: 'search_read', args: [...]})`.
- **Modify POS screen UI**: Override `OrderRow`, `ProductScreen`, `PaymentScreen` OWL components.
- **Modify business logic**: Extend `models` (e.g., `Order`, `Orderline`) to override methods like `export_for_print()`.
- **Receipt customization**: Override `pos_receipt` QWeb template.
- **Payment integration**: Implement payment service extending `AbstractPayment` — register in `payment_buttons`.

## Pitfalls

- POS is a long-lived single-page app — cache invalidation (e.g., price changes) requires session reset or custom sync.
- Custom receipt templates must handle both HTML (screen) and printable formats.
