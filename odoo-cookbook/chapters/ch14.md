## Core Concepts

- **Widget architecture**: JavaScript widgets extend `Widget` class. Use `_render()` for DOM, `_renderCustomWidget()` for custom rendering.
- **Client-side QWeb**: Templates in `static/src/xml/` with `t-name` attribute. Directives: `t-out` (safe values), `t-foreach`, `t-if`, `t-attf-class`.
- **RPC calls**: `this._rpc({model: 'hostel.room', method: 'search_read', args: [domain], kwargs: {fields: [...]}})`.

## Techniques

- **Custom field widget**: Register via `fieldRegistry.add('widget_name', WidgetClass)`. Use `<field widget="widget_name"/>` in form view.
- **Custom view**: Requires 5 components: Model, Renderer, Controller, ArchParser, View. Register in `ir.ui.view`'s `selection_add` and override `_get_view_info()`.
- **Tours**: `Tour.register('tour_name', {steps: [{trigger: 'selector', content: '...'}]})` — guides user onboarding.
- **Mobile JS**: `mobile_patch` for touch events, responsive adjustments. Use `navigator` APIs cautiously.

## Pitfalls

- `onWillRender` data re-fetch on large datasets causes repeated RPC calls and degraded performance. Prefer `onWillStart` for one-time fetches.
- Custom views are complex to implement — consider using a pre-built module from the code bundle.
