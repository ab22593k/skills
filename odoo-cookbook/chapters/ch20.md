## Core Concepts

- **Incoming mail server**: Fetchmail (`fetchmail`) — polls POP3/IMAP, creates records via `model` + `thread_id`.
- **Outgoing mail server**: SMTP via `ir.mail_server`. Per-user SMTP override in Preferences.
- **Chatter**: `mail.thread` mixin — add `_inherit = ['mail.thread', 'mail.activity.mixin']` for messages, followers, activities.

## Techniques

- **Jinja email templates**: Technical → Email Templates — use Jinja2 syntax: `{{ object.name }}`, `{% for line in object.line_ids %}`.
- **QWeb email templates**: Use `ir.actions.report` with `report_type='qweb-html'` — richer formatting than Jinja.
- **Email alias**: `mail.alias` model — routes incoming emails to model-specific record creation. Configure via `alias_id` on model.
- **Change logging**: `mail.thread` auto-logs `create()` and `write()` changes in the chatter. Customize via `_track = {'field': {'field.mapped': _('changed')}}`.
- **Periodic digest**: `mail.digest` — configurable email summaries sent on schedule.

## Pitfalls

- Email servers must be configured before any email-based features work.
- Spam filters may block Odoo-sent emails — configure SPF/DKIM records on sending domain.
- Alias routes require unique email addresses across the entire Odoo instance.
