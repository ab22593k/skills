## Core Concepts

- **WSGI + Werkzeug**: Odoo's HTTP layer. Most work at controller level: `@http.route('/path', type='http'|'jsonrpc', auth='user'|'public'|'none')`.
- **`type='http'`**: Returns HTML string (use QWeb templates, not raw HTML). `type='jsonrpc'`: Returns JSON-serializable data, requires `Content-Type: application/json`.

## Techniques

- **Controller class**: Inherit `odoo.http.Controller`. Methods decorated with `@http.route()`. Prefix paths with module name to avoid clashes.
- **Access restriction**: `auth='user'` (logged in), `auth='public'` (visitor portal), `auth='none'` (open access).
- **Parameters**: Route captures `/<int:id>` or query strings via `**kwargs`. Use `methods=['GET','POST']`.
- **Static resources**: Files in `static/` directory (e.g., `static/src/js/`, `static/src/scss/`). Served automatically at `/module_name/static/`.
- **Response control**: `request.make_response(content, headers=[('X-Custom', 'value')])` for fine-grained HTTP response.
- **Modify existing handlers**: Use view inheritance on the template or override controller method via class inheritance.

## Pitfalls

- Never generate raw HTML in controller code — use QWeb templates via `request.render()` for XSS protection.
- `type='jsonrpc'` routes reject non-JSON-RPC requests with 400 error.
- Multi-database setups need `--db-filter` for route resolution.
