## Core Concepts

- **OWL components**: `class MyComp extends Component` with `static template = "TemplateName"`. Subcomponents in `static components = { SubComp }`.
- **Lifecycle**: `setup()` → `willStart()` (async) → `rendered()` → `mounted()` → `willUpdateProps()` → `willPatch()` / `patched()` → `willUnmount()`.
- **Hooks**: `useState(initial)` (reactive state), `useEffect(fn, deps)` (side effects), `useRef(init)` (DOM refs), `useSubEnv(obj)` (environment).

## Techniques

- **Bind actions**: `<button t-on-click="() => this.doSomething()"/>` or `t-on-click.bind="this"` for method references.
- **Child-parent communication**: Parent passes callback via props: `<Child onClickUpdated={() => this.handleUpdate()}>`. Child calls `this.props.onClickUpdated()`.
- **OWL field widgets**: `class OWLFieldWidget extends Component` + `fieldRegistry.add('name', OWLFieldWidget)`. Use in form: `<field widget="name"/>`.
- **Template directives**: `t-out` (safe text), `t-raw` (HTML, XSS risk), `t-foreach`, `t-if/t-elif/t-else`, `t-attf-*` (dynamic attributes), `t-component` (dynamic component).

## Pitfalls

- Never mutate `state` directly — replace it. Always check props are read-only.
- Data fetching in `onWillRender` (runs every render cycle) causes unnecessary RPCs.
- Subcomponents must use capital-letter tag names in QWeb templates.
