## Core Concepts

- **Python test**: Extend `TransactionCase` (ORM with rollback), `SavepointCase` (allows sub-transactions), or `HttpCase` (HTTP requests).
- **HOOT (Headless Odoo Testing)**: Odoo 19's client-side test framework using Headless Chrome. Tests are JavaScript, run via Odoo's test runner.
- **Tour tests**: `Tour.register()` + `Tour.run()` — automated user flow tests that simulate clicks and form interactions.

## Techniques

- **Python test tags**: `@tagged('standard', 'slow')` — run subsets with `--test-tags standard,-slow`.
- **Run tests**: `odoo-bin -d <db> --test-enable -u <module>`. Use `--log-level=test` for detailed output.
- **Assertions**: Standard `self.assertEqual`, `self.assertIn`, `self.assertTrue`, `self.assertRaises` from Python unittest.
- **Headless Chrome setup**: `chromium-browser` + `--headless` flag. Odoo uses it for client-side test execution.
- **Client-side test debug**: Screenshots, `debug` mode in tour steps, browser devtools via `?debug=tests`.

## Pitfalls

- Tests run against the database — modules must be installed first.
- Tour tests depend on DOM structure — fragile UI refactors can break them.
- Test tags must be explicitly selected — untagged tests may be skipped.
